状态：三个实施对话代码已集成，主站本地技术链路通过；教学素材发布、头像云目录权限、隔离前端 CORS 和生产/微信真机仍有明确待办。此记录区分代码、自动测试、实际本地联调和外部验收。

## 集成结果

已整合后端 `e424183` / `d41d611`、内容 `588c282` / `9e6732f` / `6a43822`、运营 `2860f6c` / `cf86198`，以及独立内容步骤页 `3bf6671`。三份原交接记录保留；本记录补充整合后的实际证据。

- 合并两个迁移分支为 `0016_v13_unified`，两个 API 最低 schema 为 16。实际共享开发库迁移成功。
- 管理 API、内容 Worker、领域 Worker、Beat 使用同一管理镜像；用户 API 和用户 Worker 使用同一用户镜像。主站两服务共享真实 MySQL/Redis，内部 HMAC 请求实际往返。
- 发布预检查先固定旧素材、再打开发布事务；事务中再次检查固定路径、引用和状态。原图、封面、整段音频、可选词条图片/发音都受约束。批量资源操作采用同一预处理，副作用和逐项回执仍保持原子性。
- OCR 单任务、重试、批量任务使用场景当前草稿的真实模板；错误模板或旧草稿在扣额度/派发前拒绝。场景音频目标查询兼容既有 `scene:{id}` 目标和草稿显式引用。
- 内容批次恢复纳入真实 Beat 周期任务。纯标签任务不会初始化不必要的云凭据。
- 联系聚合按用户首次提交去重，修改单独计数，历史回算仅覆盖已结束的北京时间日期并保留历史状态快照。
- 头像增加本人专属上传策略、真实图片解码和服务端归一化固定复制；任意 URL、其他用户路径或不存在的校验能力均拒绝。代码与字节单测通过；真实云固定复制权限仍待补，见下文。
- 历史 `learning-card` 模板继续原样返回，目录不会因新模板枚举报 500；后台适配器对未知旧模板安全回退，不改历史数据。
- 统一导出管理端 107 个 OpenAPI 操作和用户端 57 个操作，生成契约与接口清单同步。

## 主站访问与刷新

当前保持运行：后台 <http://127.0.0.1:5173/>；管理 API <http://127.0.0.1:8000/docs>；用户 API <http://127.0.0.1:8001/docs>。

在既有本地 Docker 栈上刷新最新源码，保留运行时环境且不写 `.env`：

```powershell
cd D:\个人\juya\juya-admin-api
uv run python scripts/refresh-v13-local.py
Invoke-RestMethod http://127.0.0.1:8000/health/ready
Invoke-RestMethod http://127.0.0.1:8001/health/ready
```

此脚本针对本机已有容器，非全新环境安装器。首次须按 README 启动基础 Compose，并具备既有用户 API 的运行环境。首次缺失配置时脚本停止，不构造或保存凭据。刷新会重建镜像、迁移并重建两个 API、管理两 Worker/Beat及用户 Worker。

后台启动：

```powershell
cd D:\个人\juya\juya-admin
pnpm dev --host 127.0.0.1 --port 5173 --strictPort
```

停后台按对应终端 Ctrl+C。停止服务且保留数据库卷：

```powershell
cd D:\个人\juya\juya-admin-api
docker stop juya-main-mini-api juya-main-mini-worker
docker compose -f docker-compose.dev.yml stop
```

共享端口已占用时不要另开同端口服务；先检查 ready 与对应容器。需保留云凭据时用上述刷新脚本，直接运行默认 Compose up 可能重新采用其默认配置。本轮未推送或部署生产，未修改小程序前端。
