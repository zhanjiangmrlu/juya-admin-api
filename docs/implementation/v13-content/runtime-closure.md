# V1.3 本地收尾与真实教学素材验收（2026-10-01）

## 本次重新核实的缺口

此前的“代码已完成”记录不代表外部服务和定时执行链路已全部验收。本次重新核查发现：

1. 本地 Compose 未透传百度提供方及应用凭据，API 和内容 Worker 实际仍使用 disabled 提供方。
2. OCR 额度初次读取未成功时，前端仍可能用默认值提交；识别创建请求丢失响应后再次点击可能使用新的命令键。
3. 用户端注销调用的内部路径与管理端挂载路径不一致；缺少清理结果的持久化回传；草稿回收站缺少定时入口。反馈截图也需要区分普通在处理反馈与已完成注销授权的清理。

以上缺口已按实际代码、运行容器和 HTTP 证据补齐并验证。未修改小程序前端、未推送或部署生产。

## 注销与定时任务：已通过隔离真实链路

使用独立数据库 `juya_v13_local_e2e`、Redis `6398/0`、管理 API `18000`、用户 API `18001`。两个后端、内容/管理域/小程序 Worker 和两个独立服务的 Beat 均运行。mini 角色变量使用 `JUYA_PROCESS_TYPE=worker`，本地允许 `JUYA_ENABLE_BEAT=true`；生产继续要求每个服务独立且唯一的 Beat。

- mini 到期任务先将请求及用户置为 `DELETING`，持久化 outbox，再以真实 HTTP/HMAC 投递管理端 `/internal/v1/account-deletions`。
- 管理清理和结果 outbox 同事务持久化，带签名回调用户 API。失败时保留 `PENDING` 并按 60 秒起步退避，认领与回写使用租约条件。
- 实测正确签名但错误申请的回调被拒绝，账号仍 `DELETING`、已结单截图仍存在、清理删除 0。修复脚本自身测试记录后重新投递，双方 outbox 进入成功终态，用户及申请 `DELETED`，此时仅对应注销截图被真实 OSS 删除；普通处理中反馈截图保留。
- 未签名及错误密钥回调 HTTP 401；成功回调重放 HTTP 200，保持幂等。
- 过期草稿真实 Worker 首次清理 1、再次投递清理 0；未到期草稿保留。人工清理、恢复、自动清理共用事务锁及引用检查，已清理草稿不能恢复。并发两个操作仅一个成功，状态与修订存在性一致。
- 实际 Worker 汇总已结束日匿名测试学习事件，注销解除用户关联而保留匿名事件和汇总。

只创建和清理脚本自身隔离测试记录及测试 OSS 图片，未触发业务库的数据清理。完整证据见 [生命周期报告](evidence/runtime-lifecycle.json) 和兄弟仓库 [运行说明](../../../../juya-miniapp-api/docs/closing/runtime-lifecycle.md)。
